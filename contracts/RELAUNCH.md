# CaBi 无持仓上限版本：重新部署准备

这是一次新币发行，旧地址不会升级。本次重部署项目代币、CaBi/USDT 交易对和专用组 LP / 领取池；继续使用 BSC USDT 与 PancakeSwap V2 官方 Router / Factory。当前网站和数据库仍指向历史部署，签名前没有新的主网地址。

## 固定参数

- 总量 10 亿 CaBi、18 位精度，无增发；初始全部进入原管理员 `0xf8ada5c5052a47dc6e28a07c8a321fb1ad257d70`。
- 永久取消持仓上限，管理员不能再设回。领取、买入、普通转账均不执行持仓数量检查。交易阶段限制仍独立生效。
- 分配钱包、回购钱包、LP 接收钱包、服务器签名地址沿用已核验的公开地址，详见 `deploy/relaunch-unlimited.json`。
- 新领取池储备 7 亿枚新 CaBi；初始 LP 计划 100 USDT + 70,000 新 CaBi。用户仍按每份 15 USDT + 10,500 CaBi 组 LP，24,500 CaBi 待领。
- 首次加池由管理员稍后指定的 `seedProvider` 钱包出资，该钱包自行授权并支付两种资产和 GAS，初始 LP 直接发给它。管理员权限不转移。地址在开启组 LP 前可设置或修改，开启后锁定。
- 领取、交易时间留空。本次不会沿用旧币 2026-11-08 的时间自动开盘。

## 启动及签名

```powershell
npm run prepare:relaunch
npm run deploy:relaunch
```

打开 `http://127.0.0.1:8792/`，用管理员插件钱包连接 BSC 主网。页面依次确认六笔交易：

1. 部署永久无持仓上限的新 CaBi。
2. 创建新的 CaBi / USDT 空交易对。
3. 在新代币绑定交易对及官方 Router。
4. 部署新的组 LP / 领取池，`previousPool` 为零地址；新池独立运行，不继承旧测试池的链上领取记录。
5. 绑定新专用池。
6. 管理员向新池转入 7 亿枚新币储备。

每一步重新估算 GAS；交易参数、发送人、运行代码、配置、持仓限制标志和余额均核验后才完成。刷新或重启可恢复记录。结果文件包含参数及字节码指纹，不能混用旧部署记录。钱包 nonce 统一为十六进制字符串。

本页只需管理员的 BNB GAS；第六步转入的是第一步发行的新 CaBi。100 USDT 初始加池在后续设置时间和开启 LP 时单独确认。USDT 授权仍须钱包签名。

## 指定钱包独立加池

首次加池地址可以在六步部署之后再给。新池初始 `seedProvider` 为零，不影响部署、注入储备或先开放认购；开启组 LP 之前必须设置有效的出资地址。

网站的新入口为 `/liquidity/seed`。六步部署完成后，先按下方说明更新网站合约配置并发布此页面，再把链接发给出资人。该页面读取当前配置的代币和领取池，无需认购邀请码：管理员钱包可指定出资地址，也可点击把出资钱包缺少的新 CaBi 转给它；出资钱包自行准备 100 USDT 与 BNB。每笔资金操作仍由实际付款钱包确认。

管理员通过第二阶段控制台设置出资地址、领取/交易时间并开启组 LP 后，把网站链接发给指定钱包使用者。对方在该页精确授权 70,000 CaBi、100 USDT，再确认首次加池。页面按链上角色显示操作，不把管理员的资产授权当作出资钱包授权。

初始 LP 直接进入指定钱包，不进入用户组 LP 使用的临时托管，也不发给项目 `lpReceiver`。用户后续按认购额度生成的 LP 仍按原规则归项目钱包。首次出资者在领取尚未开放且没有用户准备额度时，可按既有 `removeSeedLiquidity` 规则退出，资产退还出资者；交易开放后可按 DEX 的普通规则操作 LP。

## 六步完成后的文件

输出在 `output/relaunch-unlimited/`，与旧 `output/launch-deployment/` 分离：

| 文件 | 用途 |
| --- | --- |
| `result.json` | 新地址、交易哈希及恢复记录 |
| `standard-input.json` / `bundle.json` | 本次完整源码、编译设置、ABI 和字节码 |
| `manifest.json` | 参数、编译器版本、指纹及准备时链上预检 |
| `website.env.pending` | 六步核验后生成的网站公开地址配置，尚未应用 |
| `stage2.template.json` | 六步完成后生成的初始加池参数，两个开放时间留空 |
| `handoff.json` | 本次独立发行、网站及后台切换步骤 |

网站切换应保留本次重置后的空业务数据库、`payment_epochs` 付款起始区块以及原管理员和服务器密钥。只合并新公开地址，给新链/代币/池组合保存暂停的组 LP 设置，再构建、发布并核对。旧付款低于重置区块的不能重新登记。原数据库和 `/etc/cabi.env` 已单独归档，不能把旧测试记录自动导回新一期。服务器私钥不写入部署产物，也不需要交给部署页面。

六步完成后，在生成的 `stage2.template.json` 填写 `seedProvider` 和新的领取/交易时间，再运行 `npm run deploy:relaunch-stage2` 打开 `http://127.0.0.1:8793/`。管理员完成指定地址、设置时间、开启组 LP 三笔交易，出资钱包另行通过网站完成首次加池。没有填写地址或时间时脚本会提示补充，不会自行代填。新池的域地址、储备、LP 归属和端到端付款 / 组 LP / 领取结果核对完成后再开放对应功能。销毁 keeper 如有运行，也要随新代币地址切换。
